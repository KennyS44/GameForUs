# Как устроен код

Дальше — устройство проекта, инструменты разработки и сеть. Что игра из себя
представляет — в [README](../README.md), полный разбор возможностей — в
[docs/design.md](design.md), настраиваемые числа — в [docs/numbers.md](numbers.md).


Главное архитектурное решение — **симуляция полностью отделена от всего
остального**:

```
src/sim/      правила игры: движение, попадания, двери, ИИ
              ни одной строчки про браузер, Three.js или DOM
src/maps/     карты как чистые данные
src/render/   Three.js: сцена, камера, эффекты
src/audio/    процедурный звук на WebAudio (звуковых файлов нет вообще)
src/input/    клавиатура и мышь -> команды для симуляции
src/net/      транспорт (WebRTC) и сессии: локальная, хост, клиент
src/ui/       HUD
vendor/       Three.js, PeerJS и CC0-текстуры Poly Haven
```

Текстуры лежат в `vendor/textures/` под лицензией CC0 — их можно использовать
как угодно, включая коммерческое. Источники перечислены в
`vendor/textures/LICENSE.txt`.

`src/net/session.js` — тот самый шов. Остальной клиент только спрашивает у
сессии состояние мира и отдаёт ей ввод. Поэтому заменить P2P на выделенный
сервер — значит поменять транспорт, не трогая правила игры.

Симуляция детерминирована и не использует `Math.random()` напрямую: разброс
идёт от seed, чтобы хост и клиент считали одинаково.

### Проверка

```
node tools/sim-smoke.mjs
node tools/map-check.mjs
```

Этот тест запускает симуляцию в чистом Node, без браузера. Пока он проходит —
правила игры действительно переносимы на сервер. Он же проверяет, что дверь
выбивается, лампа гаснет от пули, очередь убивает, а во время подготовки убить
нельзя.

Отдельным блоком он проверяет, что одиннадцать стволов ведут себя как
одиннадцать разных: зажатый спуск даёт самозарядному ровно один выстрел и
опустошает автомат, одна картечь убивает в дверях, помпа набивает трубку по
патрону, а магазин при ранней перезарядке теряется целиком. И что тяжёлое
остаётся тяжёлым: картечь не проходит сквозь гипсокартон, .50 убивает через
него, а бегут с ней медленнее, чем с обрезом.

Второй проверяет саму карту: в каждую комнату есть проход, ни один спавн и ни
одна лампа не оказались внутри мебели, а по обеим лестницам игрок действительно
поднимается на второй этаж — это проверяется прогоном настоящей симуляции.

Локальный просмотр (только для разработки, на опубликованный сайт не влияет):

```
node tools/serve.mjs 20301
```

### Снимок из игры

```
node tools/shot.mjs --weapon=ar-545-piston --ads
node tools/shot.mjs --weapon=all --out=docs/shots/{weapon}.png
node tools/shot.mjs --at=kitchen --face=dining --seconds=2
node tools/shot.mjs --list
```

Поднимает свой сервер, открывает игру в headless-браузере, ставит игрока куда
сказано, даёт ему в руки что сказано, прокручивает раунд и снимает кадр. Полный
список ключей — в шапке `tools/shot.mjs`, список комнат и стволов — по `--list`.

Два решения делают это быстрым. Раунд крутится **вручную**: `--seconds=30` не
ждёт тридцати секунд, а прогоняет 1800 тактов симуляции подряд и рисует
результат — под программным рендерером обычные часы игры идут раз в двадцать
медленнее реального времени, и именно на это уходило всё ожидание. И браузер
запускается **один раз на все кадры**: `--weapon=all` снимает одиннадцать
стволов за время чуть больше одного, потому что запуск дороже съёмки.

Кадр воспроизводим побайтово. Прицеливание, качание при ходьбе и три пружины
отдачи — единственное, что на этой сцене движется само, и `?still=1` держит их
в нуле, так что два снимка одинакового кода дают один и тот же файл. Проверено
буквально: две отдельные съёмки с зажатым спуском дали одинаковый md5. Значит,
разница между «до» и «после» — это правка, а не фаза дрожания. Ключ `--wobble`
возвращает движение, если снимать надо именно его.

Управляет всем этим `window.__gfu` — ручка, которую вешает `src/util/debug.js`.
Модуль подгружается только по `?debug=1`, поэтому на опубликованном сайте он не
скачивается вовсе и `window.__gfu` там не существует. Раньше такие хуки писались
в исходник перед съёмкой и вырезались после; вырезать больше нечего.

### Справочник прицелов

```
node tools/opticplan.mjs
```

Снимает каждый прицел через прицельное окно с одной и той же точки при
полностью поднятом прицеле и собирает [docs/optics.html](optics.html). Цифры
рядом с картинками читаются из той же таблицы, по которой работает игра, —
лист не может разойтись с тем, что игрок получит, поставив прицел.

### Чертежи оружия

```
node tools/weaponplan.mjs
```

Рисует боковой профиль каждого ствола в миллиметрах: ось канала ствола как
база, сетка 50 мм, размерные цепочки и подписанные детали —
[все одиннадцать листов](docs/weapons.html). Тот же скрипт делает из каждого
листа силуэт без бумаги — его показывает экран выбора оружия, — а
`src/render/weapons.js` собирает по этим же миллиметрам модель в руках. Одна
цифра, один ствол, три места: разойтись им негде.

### Планы этажей

```
node tools/floorplan.mjs
```

Рисует по данным карты два чертежа — `docs/plan-ground.svg` и
`docs/plan-upper.svg`: стены с их материалами, дверные проёмы со створками и
дугой хода, ступени со стрелкой подъёма, спавны и сетку в метрах. Ничего не
нарисовано руками: всё читается из того же файла, который грузит игра, поэтому
план не может тихо разойтись с уровнем. Открыть можно прямо на сайте:
[первый этаж](docs/plan-ground.png), [второй](docs/plan-upper.png).

### Выпуск новой версии

```
node tools/stamp-version.mjs
```

Хостинг отдаёт каждый файл с `Cache-Control: max-age=600` и изменить это нельзя.
Без версии в адресе браузер может собрать игру из смеси нового и старого — новый
код со старой картой. Скрипт проставляет один и тот же хеш содержимого во все
адреса модулей, поэтому новая сборка приезжает целиком или не приезжает вовсе.
Он же пишет `version.txt`: открытая страница сверяет её со своим хешем и, если
браузер показывает сохранённую копию, предлагает обновиться.

## Как работает мультиплеер

Сайт статический — своего сервера у него нет. Поэтому браузер одного игрока
становится хостом: он считает симуляцию и рассылает состояние 20 раз в секунду.
Остальные подключаются напрямую по WebRTC.

Есть короткий путь для второго окна того же браузера: они находят друг друга
через `BroadcastChannel` по коду комнаты и обмениваются теми же сообщениями, что
и по сети, — без брокера, STUN и NAT. Клиент всегда сначала спрашивает этот
канал (ответ приходит за миллисекунды) и только потом идёт в сеть. Это и есть
надёжный способ проверить PvP в одиночку: разные браузеры на одной машине так
не соединятся — у каждого свой `BroadcastChannel`.

Клиент предсказывает собственное движение локально и сверяется с хостом, поэтому
управление отзывчивое даже при заметном пинге. Свои выстрелы клиент показывает
сразу, а попадания и смерти берёт только от хоста — он единственный авторитет.

Единственный внешний сервис — бесплатный брокер PeerJS, который нужен только
чтобы два браузера нашли друг друга.

**Честные ограничения этой схемы:**
- хост закрыл вкладку — матч закончился;
- у хоста нет пинга к самому себе, у него преимущество;
- античита нет: хост видит всё состояние мира;
- при строгом NAT у обеих сторон прямое соединение может не установиться. На
  этот случай подключены бесплатные публичные TURN-ретрансляторы, но они не
  гарантия: сервис общий, может быть перегружен или вовсе закрыться — так уже
  случилось с прежним ретранслятором в этом списке;
- два игрока за одним роутером — не самый простой случай, а самый неудобный:
  снаружи у них один и тот же адрес, значит соединяться нужно по локальному, а
  локальные адреса браузер прячет за mDNS-именами `.local`, которые другой
  браузер часто не может разрешить. Тогда спасает только ретранслятор.

Как отличить одно от другого по сообщению на экране: «комната с таким кодом не
найдена» приходит за секунду и означает опечатку или что хост вышел. Если хост
найден, но канал не открылся, сообщение говорит ещё и почему: «ретранслятор
недоступен» — до TURN-серверов не достучались, фолбэка не было вовсе; без этой
приписки — ретранслятор был, а пара всё равно не сошлась. В обоих случаях
помогает другая сеть или смена ролей.

Всё это уходит, когда симуляция переезжает на выделенный сервер. Код к этому
готов: `src/sim/` запускается под Node как есть.
